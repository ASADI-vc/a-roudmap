- **Source type:** official documentation (consensus body-of-knowledge guide; curriculum-foundation reference)
- **Research questions addressed:** RQ1 (durable foundations for AI-era engineers); partially RQ2/RQ3 not addressed (this source defines SE knowledge, not learning techniques)
- **Original summary (own words):** The SWEBOK Guide V4.0 page describes the guide as consensus-driven, "generally accepted" knowledge of software engineering organized into 18 knowledge areas (KAs). Version 4.0 adds three new KAs — Software Architecture, Software Engineering Operations, and Software Security — and integrates Agile and DevOps into several existing KAs, while retiring outdated content. The guide explicitly distinguishes a body of knowledge from a curriculum: SWEBOK defines the core of the discipline, and curriculum/accreditation bodies decide what lies beyond it. The page also states the guide is intended as a foundation for training materials, curriculum development, certification, and licensing. Development is consensus-based with public review, and a Version 5.0 effort is underway via town halls.
- **Relevant findings:**
  - 18 KAs in V4.0; the chapter list on the page: Software Requirements; Software Architecture; Software Design; Software Construction; Software Testing; Software Engineering Operations; Software Maintenance; Software Configuration Management; Software Engineering Management; Software Engineering Process; Software Engineering Models and Methods; Software Quality; Software Security; Software Engineering Professional Practice; Software Engineering Economics; Computing Foundations; Mathematical Foundations; Engineering Foundations (section "About SWEBoK" / webinar chapter list).
  - "three new knowledge areas—Software Architecture, Software Engineering Operations, and Software Security—have been added" and "Agile and DevOps have been notably integrated into several KAs" (section "About SWEBoK").
  - Rising importance of security explicitly named as a driver of revision: "the importance of security in good software development has become increasingly clear in recent years" (section "An Evolving Body of Knowledge").
  - "Generally accepted" operationalized by the Industrial Advisory Board as knowledge for a licensing-exam study body "that a graduate would pass after completing four years of work experience"; KA editors should consider what will be generally accepted "in a 3 to 5 year timeframe" (section "Focus on Generally Accepted Knowledge").
  - Stated purposes include "Provides a foundation for training materials and curriculum development" and "Supports certification and licensing of software engineers" (section "About SWEBoK").
  - Guide "will remain freely accessible in at least one format" (transparency/wide-distribution principles, section "About SWEBoK").
  - AI/ML-assisted software engineering: NOT detailed anywhere on the landing page; "AI" appears only in a cited reference (I. Ozkaya, "An AI Engineer Versus a Software Engineer," IEEE Software, Vol. 39, No. 6, 2022) within the reference lists shown.
- **Population / methodology / tools:** Not an empirical study. Consensus-editor process: named KA editors from industry/academia (e.g., Steve Tockey, Rich Hilliard, Francis Bordeleau, Nobukazu Yoshioka/IBM Research for Software Security), public review, ISO/IEC-standards appendix; developed under the IEEE CS Professional Activities Board.
- **Limitations / conflicts of interest / applicability:** Landing page only; the full PDF sits behind a download form, so per-KA detail (e.g., exactly how AI/ML-assisted SE is treated inside Construction or Testing KAs) could not be verified. Vendor/standards-body positioning (self-described as "most authoritative") should be read as promotional framing. Applicability: strong for RQ1 claims about what the SE profession treats as durable, consensus fundamentals (incl. security and operations), weak for anything about AI-era specifics beyond what is visible.
- **Candidate claims supported:**

  - observed — IEEE CS explicitly positions SWEBOK as a foundation for curriculum development, certification, and licensing of software engineers.
  - observed — V4.0 integrates Agile and DevOps content and names security's rising importance as a revision driver.

- **Implications for learners:** The consensus core an AI-era engineer must retain includes classical SE areas plus security and operations as first-class knowledge; a curriculum can map its "durable fundamentals" layer onto the 18 KAs while treating fast-moving tooling as outside the core.
