- **Original summary (own words):** WCAG 2.2 is the W3C Recommendation defining testable success criteria for web content accessibility, organized under four principles — Perceivable, Operable, Understandable, Robust (POUR) — with three conformance levels (A, AA, AAA). It extends WCAG 2.1 additively, adding nine new success criteria (e.g., Focus Not Obscured, Target Size (Minimum), Dragging Movements, Consistent Help, Redundant Entry, Accessible Authentication) and removing the 4.1.1 Parsing criterion. The document explicitly recommends that sites adopt WCAG 2.2 as their conformance target even where policies still cite earlier versions.

The Privacy/Security Considerations sections bridge accessibility to the security curriculum thread.
- **Limitations:** WCAG 2.2 is content-focused and normative-dense — curriculum should link the paired "Understanding"/"How to Meet" docs for teaching rather than raw criteria text. Level AA is the usual policy target while AAA is aspirational for whole sites (conformance wording as served). A major version (WCAG 3) is in development (stated in "Later Versions of Accessibility Guidelines"), so long-lived curricula should re-check the conformance-target landscape.
- **Candidate claims supported:** recommendation — teach POUR and the A/AA/AAA conformance model from the normative text; recommendation — adopt WCAG 2.2 as the conformance target per the AG WG's stated recommendation; recommendation — cover the new 2.2 criteria (focus visibility, target size, authentication) in forms/UI lessons.
- **Implications for learners:** Learners should map each new UI pattern to POUR and know which level (A/AA/AAA) a criterion carries; they must also learn the practical policy nuance — conforming to 2.2 implies 2.1/2.0 conformance, but policy-mandated 2.0/2.1 reporting may still require testing the removed 4.1.1.
